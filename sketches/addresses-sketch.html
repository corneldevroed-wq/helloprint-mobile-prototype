My account: Addresses

Cornel chose B (2026-11-18): the address cards of the customer journey, so it's all the same; built as prototype/addresses.html. My pick was A. The same settings list as Personal details: on top the two addresses that matter for every order (Default shipping, Billing), each a row with its icon and one button; under it All addresses, a row per address with Edit, and New address last. Edit and Add open our standard popup with the checkout's address form. The two account pages then work exactly the same, it reads fast, and on mobile nothing gets cramped. B uses the checkout's address cards: familiar from the checkout, but cards with three links each get busy, and Default / Billing as labels on a card are easy to miss. C is the artifact 1:1 (two cards + a table): clear on desktop, but the table needs its own rows on mobile.
  • From the artifact: default delivery, billing (with the company and VAT number), more addresses, add an address.
  • Ours: the address book is the checkout's ('hp-addresses'), so what you add here is at the checkout and on the order page's Change, and back; "shipping address", never delivery address.
  • Only UI guide parts: the setting row (.has-ico + .hc-ico), .dash-card, the address book cards (B), .dash-table (C), .badge.neutral, the popup.
