Brief (Cornel, 2026-11-08): the confirmed page has several states and has to be strict about them: files still to upload, files and payment, payment only, and with more order lines the situation differs per line. The status timeline can't only sit on top of the page: with more lines it belongs to the line.

The model: files are per order line (upload later / designed online / uploaded on the PDP). Payment is per order (Pay now, or Pay later = one payment link). Status and delivery date are per order line. Deadline: files approved and the order paid by 10:30 the working day before, to keep each line's date.

Example: Anna, order HP-IE-7762447, €44.13 (one line) / €92.40 (three lines). Drawn on mobile; desktop puts the same in the 544 column, with the Order overview card on the right (confirmed-desk-sketch.html A). NEW marks parts that don't exist yet.

Rules for the build (my proposal)

  • One template, two layouts: 1 line → to-do + page timeline; 2+ lines → order to-do + line cards. The page picks by the number of lines.
  • The to-do only shows what the customer still has to do; it shrinks as they do it (upload done → that item turns into "File received, we're checking it").
  • Orange = waits on you (the label colour for urgency we already have), green = done, grey = later. No other colours.
  • Payment is never per line: one "Pay €… now" for the order, with "we also emailed you the link". Paying here = the same link.
  • Every deadline in the same words: "by 10:30 on Mon 28 Sep to keep delivery on Tue 29 Sep"; with more lines, each card has its own date.
  • Order overview, shipping address and the questions stay under it as now (desktop: the overview card on the right).
  • No way back into the checkout: the order is placed and the cart is empty, so every step is a plain done step (no back button to Cart, no links to Details or Payment). The only way on is Continue shopping.
