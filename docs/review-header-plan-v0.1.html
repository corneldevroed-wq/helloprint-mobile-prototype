Header plan review against the prototype and the UI Style Guide

For Sebastiaan Ram · from Cornel de Vroed (design) · 13 Nov 2026 · checked against helloprint-design@0f4a240, the same commit the plan pins (no newer prototype changes).

In short

The plan follows the prototype closely and the code references to app.js and decisions.md are correct. Seven points need a fix, four need a decision, and the plan underuses one source: the UI Style Guide. It has a row for every header component with its exact rule, rendered live from the same CSS as the prototype, and it fills most of the gaps below.

Points to fix

Fix

1 · "Delivery, never shipping" contradicts our naming

Plan (For Agents → Guardrails)“customer copy says ‘delivery’, never ‘shipping’”.
Prototype ruleIt is shipping address (never delivery address) and billing address (never invoice address). Delivery is only the delivery option (Saver / Standard / Express), shown as “Estimated <day> — latest <date>”.

Fix: replace the guardrail with these three naming rules. Every ticket that comes out of this plan inherits it.

Fix

1b · The brand is always HelloPrint, with a capital P

PlanWrites “Helloprint” throughout, and the guardrail says “the brand is written ‘Helloprint’”.
RuleIt is always HelloPrint, capital H and capital P, in every text, label, alt text and key the customer can see. The prototype follows this.

Fix: turn the guardrail around (“the brand is written HelloPrint”) and correct it everywhere in the plan.

Fix

2 ·The desktop USP bar is light grey, not white (C7)

Plan“one white row under the category bar”.
Prototype + UI guide.dusps and .usp are --light-grey (#f0f0f0), 30 px high on mobile. UI guide → Header & footer → USP bar: “Light grey: the Trustpilot reviews first, then the USPs (a ticker on mobile).”

Fix: “one --light-grey row”, same on mobile and desktop.

Fix

3 · Drop menu sizes are not the same everywhere (Shared definitions, C4, C6)

PlanDrop menu: “320 wide, rows of 40, 18 px icons”. C6 says “dark grey 20 px icons”.
Measured in the prototype
  • Need help? and the account menu: 320 wide.
  • Country menu: 240 wide, rows of 40.
  • A row with a sub line (Need help?) is 48; without one (account pages, countries) 40.
  • Icons 18 everywhere (the 20 in C6 is from 11-11 and was replaced by the compact decision of 11-12).
  • Mobile account sheet: rows of 48 for a finger.

Fix: take the sizes from the UI guide rows “Drop menu”, “Account menu” and “Country menu” (each lists them), and remove the 20 px from C6.

Fix

4 · Every dark layer also blurs the page (Shared definitions → Overlay, C8, C9)

PlanOverlay = --overlay black 60%, 0.25 s fade.
Prototype + UI guideDecided 11-13: --overlay plus backdrop-filter: blur(4px) under every popup and sheet, the mobile drawer, the mega menu and the search dropdown. The guide’s Colours → Overlay token already says so; decisions.md did not yet, it is added now.

Fix: add the 4 px blur to the overlay definition (and to the CWV check: a backdrop blur on a full-page layer costs paint on low-end phones).

Fix

5 · The desktop search dropdown falls between two plans (C3)

Plan“What the search shows stays in plan 3.”
Why that is a gapPlan 3 v0.2 is from 18 Oct. The desktop dropdown was decided on 11-13, so plan 3 does not describe it:
  • a dropdown under the field, as live en-ie;
  • categories left (the mega menu side list), product rows right;
  • at most 6 products, a “From” price only (not bold), the arrow at the end;
  • empty: Popular searches as pills, then Best Sellers;
  • “View all results for …” in the link style.

Fix: add an open question that plan 3 v0.3 takes over the UI guide row “Search dropdown” (and the mobile row “Search”), or move it into this plan as C3b.

Fix

6 · Design sign-off contradicts itself (Ready for sign-off vs OQ-S2)

Plan“Cornel signs that the wireframes match the prototype”, while OQ-S2 proposes Cornel as consulted, not an approver.
ProposalCornel signs off the visuals (design reference per ticket and the UI guide rows), not scope or tech. Otherwise the design can drift during the build without anyone noticing.

Fix: make Cornel the visual sign-off in OQ-S2 and keep the line under “Ready for sign-off”.

Decisions to settle

OQ-C1

Notice colour

C1 records Cornel’s choice (light green with white, 3.2:1); OQ-C1 still proposes --link. Cornel chose light green after seeing both. Keep C1 as decided and leave OQ-C1 only as an accessibility note: dark green text on light green is the fallback that passes (4.9:1), if WCAG AA is made a hard gate.

OQ-S3

Mobile header height

The plan proposes (b): the search row scrolls away. The prototype keeps both rows sticky (89 px, about 10% of a 844 px screen). Design pick: (a), the prototype. On mobile the search is the main way in, and it is the reason the field sits in the header at all. (b) is acceptable as a fallback only if CRO data shows the height hurts.

Agree

Deliberate deviations from the prototype

  • Hit areas of 44×44 around the 24 px header icons, and 44 for the notice close (prototype 32).
  • A 16 px search input on mobile (prototype 14) so iOS does not zoom. The field looks slightly bigger; fine.
  • Additions not in the prototype: logged-in drawer foot (My account + Log out), the phone only within opening hours, the cart badge, MiniCart instead of the cart page (OQ-M4).
Agree

Prototype faults the plan rightly does not take over

  • “Stationary”, and bar labels that differ from the drawer and the mega panel title (“Promotional Print” vs “Promotional Prints”, “Books” vs “Booklets”).
  • Sverige and two Belgium rows in the country list; Clothing in Ireland.
  • Menu rows as <button> without a link, panels built on tap, hidden on closed menus.

The UI Style Guide as a source

The plan points to the guide once (“Patterns → Header & footer”) and otherwise takes its design reference from the prototype pages and the inline wireframes. The guide is the better reference for engineering: one row per component, the real classes, a live example rendered from design-system/components.css and tokens.css, and the rule in words with the decision date. When the prototype page and the guide differ, the guide wins; it is updated in the same change as every component.

Proposal for the plan
  • Add a “UI guide row” column to the build batch table and cite the rows below per ticket.
  • Name the three files as the style source: design-system/tokens.css (colours, radius, type sizes, line heights), design-system/components.css (every component, mobile and .desk), design-system/icons/ (Material Symbols Rounded, the only icon set). prototype/pages.css only for page-specific tweaks.
  • Use the guide’s Mobile / Desktop toggle for review: it shows each component at 390 and at desktop width.
